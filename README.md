# Letter Assistant

> Helping people in Germany understand and respond to official German letters — in their own language.

**Live Demo:** `https://official-letter-assistant.vercel.app`

---

## Overview

Letter Assistant is a task-specific AI assistant for German official letters. Rather than providing a literal translation, it extracts what matters: what the letter is about, how urgent it is, what actions or documents are required, payment details, possible consequences, and points that need a second look.

The system also supports guided follow-up questions, grounded open chat, multilingual output, and formal German reply draft generation. It is designed to assist comprehension and response drafting — not to provide legal advice.

---

## Why Letter Assistant

- **Real problem, real users.** Germany has one of the most document-heavy administrative systems in the world. International residents regularly receive official letters they cannot fully understand — with real deadlines and real consequences.
- **Extraction over translation.** The system does not translate the letter word-for-word. It identifies what the user needs to act on: deadlines, required actions, payment details, and risks.
- **Grounded by design.** All follow-up answers, chat responses, and reply drafts are grounded in the uploaded letter — not in general knowledge. The system is designed to reduce hallucination by grounding follow-up answers, chat responses, and reply drafts in the uploaded letter and structured analysis.
- **Transparent quality signal.** A rule-based confidence label tells users how reliably the letter was analyzed — calculated from structured output, not generated by the LLM.
- **Privacy-first.** No letter content is stored. All processing is in-memory only.

## Features

| Feature | Description |
|---|---|
| Text, PDF, and image input | Paste text, upload a PDF, or photograph a letter |
| OCR fallback | Scanned PDFs and images processed automatically with GPT-4o Vision |
| Letter verification | Non-letter content classified in the analysis flow and returned as a compact rejection response |
| Structured extraction | Sender, urgency, deadlines, actions, documents, payment, consequences |
| Rule-based quality label | Confidence level calculated in backend logic — not generated by the LLM |
| Guided follow-up | Four predefined questions: payment, documents, consequences, things to watch out for |
| Grounded open chat | Answers based on the uploaded letter only, not general knowledge |
| Reply draft | Formal German reply with three selectable intents |
| Multi-language output | Full analysis and chat in 16 supported languages |
| Language switching | Re-translate an existing analysis without re-uploading (`/translate`) |
| Privacy | No letter content stored; all processing is in-memory |

## How It Works

```
Letter (text / PDF / image)
   │
   ▼
Text extraction (pdfplumber / GPT-4o Vision OCR)
   │
   ▼
Structured LLM analysis + rule-based quality label
   │
   ├── Guided follow-up questions
   ├── Grounded open chat
   ├── Reply draft generation
   └── Language translation
```

## Getting Started

### Backend

```bash
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Create `backend/.env`:

```
OPENAI_API_KEY=your_key_here
OPENAI_MODEL=gpt-4o
CORS_ORIGINS=http://localhost:5173,https://official-letter-assistant.vercel.app
```

The remaining timeout and input-limit settings are documented in
[`backend/.env.example`](backend/.env.example).

```bash
python3 -m uvicorn app.main:app --reload
# → http://localhost:8000
```

### Frontend

```bash
cd frontend
npm install
npm run dev
# → http://localhost:5173
```

## API

| Endpoint | Method | Description |
|---|---|---|
| `/analyze-text` | POST | Analyze pasted letter text |
| `/analyze-pdf` | POST | Analyze uploaded PDF or image |
| `/follow-up` | POST | Answer one of four guided questions |
| `/chat` | POST | Stream grounded open-chat responses using SSE |
| `/reply-draft` | POST | Generate one complete formal German reply |
| `/translate` | POST | Re-translate an existing analysis into a different language |
| `/health` | GET | Check backend availability |
| `/ready` | GET | Check whether the LLM provider is configured |

All user-facing LLM endpoints accept an optional `output_language` parameter (default: `"English"`).

Full reference: [docs/API.md](docs/API.md)

## Evaluation

The backend was evaluated with a golden set of 10 synthetic German official letters covering multiple sender domains and specific edge cases. In the final evaluation workflow, the system produced no FAIL or ERROR results. Most PARTIAL results were caused by strict keyword matching, borderline urgency interpretation, or minor extraction wording differences — not by complete analysis failures. A separate stability analysis confirmed that urgency and confidence labels remained consistent across repeated runs for 8 out of 10 samples.

Full methodology and detailed run results: [docs/EVALUATION.md](docs/EVALUATION.md)
